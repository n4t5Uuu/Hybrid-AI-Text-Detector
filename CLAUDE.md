## Ponytail

On every coding task (writing, fixing, refactoring, reviewing, choosing dependencies), apply the Ponytail skill when it helps: the smallest change that fully solves the task, and a reply the user can read in one pass. Use `/ponytail-review` for code reviews. Skip it for pure questions or non-code work.

## UI changes

When asked to design, redesign, critique, polish or otherwise change the web app UI (`src/app/`), use the Impeccable skill: invoke `/impeccable` with the fitting command (`critique`, `audit`, `polish`, `shape`, `distill`, `harden`, `animate`) instead of editing styles ad hoc. If `PRODUCT.md` does not exist yet, run `/impeccable init` first. Not needed for backend, notebook or data-pipeline work.
